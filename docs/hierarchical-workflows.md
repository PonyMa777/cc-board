# 层级任务与验收边界

新任务发送箭头悬停、点击菜单或键盘打开菜单后，可选一次性、复杂任务、先讨论方案。
悬停只显示菜单，选模式不提交；讨论必须通过明确执行按钮确认当前方案版本。

复杂任务由真实 Codex 线程组成：YOU（你／当前对话）代表用户目标入口，
总负责人按任务需要委派拆解、研究、实现、文档、独立测试和验收。每次负责人决策与专业
阶段均创建独立线程，前序报告作为数据传递，持久记录真实父线程与轮次编号。
这不是将一个提示词假扮为多名助手，也不是接管任意桌面聊天。
当前主聊天 ID 不能自动绑定成 CCBoard 的执行通道。可行入口是在 CCBoard 新任务中
填写任务目标、目录和必要背景，再明确提交；外部聊天的继续沟通仍在原聊天进行。

总负责人使用用户指定的 `gpt-6.2-astra` / `high`，每个复杂任务先通过 `model/list`
核验可用性，再检查 `thread/start` 返回的实际模型；无法核验、不可用或服务重路由时
停止，不静默降级。其他角色沿用提交时模型配置，未指定时沿用 Codex 默认。

负责人动态决定下一项委派或收尾，最多 12 个阶段、2 次验收返工。
写入版本变化后旧验收不再有效。没有当前版本的宿主测试证据和独立验收就不能完成。
同一或嵌套工作目录禁止并发写任务；取消或重启后不确定的远端写阶段保留目录占用，
用户核对助手已停止后可明确解除，但不会重放任务。

讨论、负责人、拆解、验收阶段仅获得受限文件快照，禁用命令、Apps、MCP、浏览器、
代码执行、hooks 等工具；研究阶段只额外启用官方内置网页检索。
实现和文档阶段执行已授权工作，明确使用项目目录和专用临时目录的 workspace-write 沙盒；遇到审批或用户输入不会自动批准。
独立测试助手在 `D:\ChatGPT-Temp` 下使用 workspace-write 沙盒执行命令，
仅独立测试目录可写，作为兄弟目录的被测项目副本只读。
禁止网络、Apps、MCP、浏览器与权限提升，不改原项目。宿主记录真实 commandExecution
事件的命令、退出码、输出、线程轮次和副本哈希，以及命令引用的脚本内容和新增测试文件；
测试修改了已复制源文件则拒绝交付，原项目发生变化也不能用旧证据完成。
验收助手必须引用对应宿主证据 ID，不能用自报证据类型冒充真实执行。
副本排除依赖目录、隐藏项、敏感命名及链接；缺少依赖、权限、网络或真实外部环境时
必须受阻，不自动绕过限制。隔离测试不等于真实桌面验收。
涉及归档、锁和服务占用的任务，测试指令明确要求假 HOME、双服务占用场景。
不得将操作助手自述、网页资料或静态快照写成独立的真实环境测试结果。

报告将证据区分为真实环境、隔离验证和静态审查，并显示实际模型、线程与父节点。
Windows 组织图不按标题推断管理关系；只把工作流实际创建的父子关系连线，
已归档或未列入当前目录的线程仍可在任务流程记录中查看身份与交付。

测试分层：调度与图关系使用模拟执行器；UI 使用合成 API 和真实 Chromium；
安装协议验证用隔离 HOME，拦截全部 `turn/start`，验证模型回传与工具隔离。
这些测试不等于用户业务的端到端验收，未对已有真实聊天做业务测试。
