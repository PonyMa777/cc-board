# 回顾进展

无需离开 CCBoard：

- 普通任务卡顶部的回顾按钮（窄卡显示 ↶，悬停显示“回顾进展”）。
- 组织图节点展开浮层中的“回顾进展”。
- 对话详情顶部的“回顾进展”。

面板先展示原始目标、助手曾报告的进展、最近用户问题及助手结论，并把看板自动
识别的待跟进句放回原文上下文。历史背景和完整对话默认折叠；“查看原文”可直接
定位该条记录，原始对话按日志顺序分批展开。

这是**提取式回顾**，无需模型或网络生成，不会根据末句猜测整个任务。助手原文
中的完成声明未经过独立验证，计划和建议也不等于已执行。反问、小标题可能被旧的
待跟进识别误判，面板明确提示这一点；不会擅自把原卡标成已处理或修改既有状态。

例如，房价讨论中的“那它对你们有什么用？”可能只是助手回答中的反问标题。
回顾同时展示最近关于 OLS 与 gradient descent 的用户提问，以及标题后面的回答，
不会把它直接改写成“你现在必须回答这个问题”。

## 数据与限制

`GET /api/recap?sid=...` 只读取已经登记的会话日志，不能任意指定文件路径。
既不向原聊天发消息，也不启动、恢复业务任务或修改已读/已完成状态。
旧的对话详情在 Windows 上错误选择解析器的问题也已修复。

日志默认最多读取 32MB，超过时读首尾并标注中间缺段；正文最多保留 2000 条消息、
4MB 文本，单条最多 1MB。超限保留首尾，原文展开也会明确说明不完整。自动环境包装
和工具输出不当作用户目标，继承的父聊天上下文单独标记；重复日志表示只在相邻、
无边界的情况下去重，真实重复提问仍保留。损坏行会中断回合配对，不能跨缺口猜关系。

缓存基于文件身份、长度和修改时间版本，最多四份/约16MB；并发读取合并。打开面板
期间每10秒检查版本，变化或无法检查时提示可能过期，用户点击“更新回顾”重读。
缺失、不可读、损坏、截断和可读但没有可识别交流是不同情况，不会统一说“没有历史”。

验证：`node test/recap.test.mjs`（19项合成日志）、`node test/recap-api.test.mjs`
（鉴权、只读、版本、Windows解析器）、`node test/recap-ui.test.mjs`（真实Chromium、
合成API与对话）。真实指定聊天只做了只读文字核对；视觉验证使用合成房价示例。
